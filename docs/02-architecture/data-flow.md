# Data Flow Architecture

## Overview
This document describes how data flows through the dashboard system, from sources through transformation and storage to final presentation.

## Data Flow Patterns

### Read Flow
```
Data Source → Fetch → Transform → Cache → Render → Display
```

### Write Flow
```
User Input → Validate → Transform → Persist → Broadcast → Update Views
```

### Update Flow
```
Change Event → Diff → Validate → Apply → Persist → Notify → Re-render
```

## Data Sources

### Static Data
Data embedded directly in tile configuration.

```typescript
interface StaticDataFlow {
  source: TileConfig;

  read(): Data;
  update(data: Data): void;
  validate(data: Data): boolean;
}
```

**Flow:**
1. Data stored in tile config
2. Loaded with tile
3. No external fetching required
4. Updates require tile save

### Dynamic Data
Data fetched from external sources.

```typescript
interface DynamicDataFlow {
  source: DataSource;

  fetch(): Promise<Data>;
  subscribe(callback: DataCallback): Unsubscribe;
  refresh(): Promise<Data>;
  cache?: CacheStrategy;
}
```

**Flow:**
1. Configuration defines source
2. Fetch on load/interval
3. Transform to expected format
4. Cache for performance
5. Update on refresh

### Imported Data
Data imported from CSV files or clipboard.

```typescript
interface ImportedDataFlow {
  source: 'file' | 'paste';

  parse(input: File | string): Promise<ParsedData>;
  profile(data: ParsedData): DataProfile;
  store(datasetId: string, data: any): Promise<void>;
  retrieve(datasetId: string): Promise<Dataset>;
}
```

**Flow:**
1. User uploads CSV or pastes data
2. Parse and validate
3. Detect column types
4. Profile data (statistics, quality)
5. Store in IndexedDB + server
6. Generate chart recommendations
7. Create tile from data

### AI-Generated Data
Chart configurations generated by Chart-MCP.

```typescript
interface AIGeneratedDataFlow {
  intent: string;
  data?: Dataset;

  generate(options: GenerateOptions): Promise<ChartOption[]>;
  recommend(datasetId: string): Promise<Recommendation[]>;
  subscribe(onProgress: ProgressCallback): Unsubscribe;
}
```

**Flow:**
1. User provides intent (natural language)
2. Optionally attach dataset
3. Send to Chart-MCP via WebSocket/REST
4. Receive real-time progress updates
5. Get multiple chart options
6. User selects best option
7. Create tile from chart config

### Computed Data
Data derived from other data sources.

```typescript
interface ComputedDataFlow {
  dependencies: DataSource[];

  compute(inputs: Data[]): Data;
  invalidate(): void;
  memoize?: boolean;
}
```

**Flow:**
1. Monitor dependencies
2. Recompute on change
3. Cache results
4. Propagate updates

## State Management

### State Layers
```
Application State
    ├── Database State (SQLite - persistent)
    │   ├── Templates
    │   ├── Instances
    │   ├── Layouts
    │   └── Positions
    ├── IndexedDB State (client - cached datasets)
    ├── React Context State (session)
    │   ├── TileContext
    │   ├── LayoutContext
    │   ├── SidebarContext
    │   └── DataImportContext
    └── Local State (component)
```

### State Synchronization
```typescript
interface StateSync {
  // Database to Context
  loadFromDatabase(): Promise<void>;

  // Context to Database
  saveToDatabase(): Promise<void>;

  // IndexedDB for datasets
  cacheDataset(dataset: Dataset): Promise<void>;
  retrieveDataset(id: string): Promise<Dataset>;

  // Cross-component
  broadcast(event: StateEvent): void;
  subscribe(listener: StateListener): Unsubscribe;
}
```

### Database Persistence Flow
```
User Action → Context Update → Service Layer → Database → Confirmation
```

**Example: Creating Instance**
```
1. User clicks "Add to Dashboard"
2. TileContext.createInstance(templateId, layoutId)
3. TileInstanceService.createInstanceFromTemplate()
4. INSERT into tile_instances table
5. Context updated with new instance
6. UI re-renders
```

## Caching Strategy

### Cache Hierarchy
```
Memory Cache (L1)
    └── Session Storage (L2)
        └── Local Storage (L3)
            └── Database (L4)
```

### Cache Policies
```typescript
interface CachePolicy {
  ttl?: number;              // Time to live
  maxSize?: number;          // Maximum entries
  strategy: 'LRU' | 'LFU' | 'FIFO';
  invalidation: InvalidationStrategy;
}

interface InvalidationStrategy {
  onWrite?: boolean;         // Invalidate on write
  onTimeout?: boolean;       // Invalidate after TTL
  onEvent?: string[];        // Invalidate on events
}
```

### Cache Flow
```
Request → Check L1 → Check L2 → Check L3 → Fetch → Store → Return
```

## Real-time Updates

### Update Mechanisms

#### Polling
```
Set Interval → Fetch → Compare → Update if Changed
```

#### WebSocket (Chart-MCP)
```
Connect → Subscribe → Receive Updates → Apply Changes
```

**Chart Generation Flow:**
```
1. Open WebSocket connection to Chart-MCP
2. Send generation request
3. Receive progress events:
   - planner (0-16%)
   - compiler (17-33%)
   - renderer (34-50%)
   - ranker (51-66%)
   - beautifier (67-83%)
   - optimizer (84-100%)
4. Receive complete event with chart options
5. Close connection
```

#### Server-Sent Events
```
Open Connection → Receive Events → Process → Update State
```

### Update Flow
```typescript
interface RealtimeFlow {
  connect(): Promise<Connection>;
  subscribe(channel: string): Subscription;

  onUpdate(handler: UpdateHandler): void;
  onProgress(handler: ProgressHandler): void;  // For Chart-MCP
  onError(handler: ErrorHandler): void;

  disconnect(): void;
}
```

### Chart-MCP Real-time Flow
```typescript
interface ChartMCPRealtimeFlow {
  // WebSocket connection
  ws: WebSocket;

  // Progress tracking
  onProgress(stage: string, percent: number, message: string): void;

  // Completion
  onComplete(charts: ChartOption[]): void;

  // Error handling
  onError(error: Error): void;
}
```
